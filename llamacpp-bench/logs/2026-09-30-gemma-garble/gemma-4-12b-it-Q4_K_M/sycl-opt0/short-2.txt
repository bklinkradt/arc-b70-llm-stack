To accomplish this, the most efficient way is to use the `find` command to list files, `du` to calculate sizes, `sort` to order them, and `head` to limit the results.

Here is a robust script to do this:

```bash
#!/bin/bash

# Check if a directory argument was provided, otherwise use the current directory
TARGET_DIR=${1:-.}

# Check if the provided path is a valid directory
if [ ! -d "$TARGET_DIR" ]; then
    echo "Error: $TARGET_DIR is not a valid directory."
    exit 1
fi

echo "Finding the 10 largest files in: $TARGET_DIR"
echo "--------------------------------------------------"

# Explanation of the command chain:
# 1. find: Looks for files (-type f) recursively.
# 2. xargs -r: Passes the file list to the next command (handles spaces in filenames).
# 3. du -ah: Gets the size of each file in human-readable format (K, M, G).
# 4. sort -rh: Sorts by numbers (-n) in reverse (-r) using human-readable suffixes (-h).
# 5. head -n 10: Takes the top 10 results.

find "$TARGET_DIR" -type f -print0 | xargs -0 -r du -ah | sort -rh | head -n 10
```

### How to use it:

1.  **Create the file:**
    `nano find_large_files.sh`
2.  **Paste the code above into the file.**
3.  **Make the script executable:**
    `chmod +x find_large_files.sh`
4.  **Run the script:**
    You can run it on the current directory:
    `./find_large_files.sh`
    Or specify a path:
    `./find_large_files.sh /var/log`

### Key features of this script:
*   **Handles Spaces:** By using `-print0` and `xargs -0`, the script won't crash if your filenames contain spaces or newlines.
*   **Human Readable:** It uses `du -h` and `sort -h` so you see "1.2G" instead of "1258291234" bytes.
*   **Recursive:** It searches all subdirectories automatically.
*   **Error Handling:** It checks if the directory you provided actually exists before trying to scan it.
